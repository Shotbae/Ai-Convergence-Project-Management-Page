# 적용 및 사용 안내

## 적용할 코드

이번 전달 파일은 [전체 코드 확인본 2026-11-05.2](../releases/AI융합_전체코드_2026-11-05.2.txt)다. 기존 기능과 새 기능이 모두 들어 있으며, 첫 줄에 `전체 코드 확인본: 2026-11-05.2`가 표시된다. 루트의 `aiconvpromanage.gs`는 개발 원본이며 이 확인본과 같은 내용인지 자동 시험한다.

1. 운영 스프레드시트를 복사해 테스트용 사본을 만든다.
2. 사본에서 확장 프로그램 → Apps Script를 연다.
3. 기존 전체 코드를 백업한 뒤, 기존 코드 파일 내용을 위 **전달 확인본 전체 내용**으로 교체하고 저장한다.
4. 같은 전역 함수가 있는 기존 코드와 새 전체 코드를 두 파일에 중복으로 넣지 않는다. 다른 용도의 기존 스크립트가 있다면 `onOpen`·`onEdit` 중복 여부를 확인한다.
5. 스프레드시트를 다시 열어 `⚙️ 출석부 관리` → `🧪 온점 검사 작동 확인`을 실행한다. `2026-11-05.2`와 문장 중간·문장 끝 두 항목의 `정상` 표시를 확인한다.
6. `🔎 세특 전체 재검증 (이어서 처리)`를 실행한다. 결과 안내에 `온점 검사 포함 / 2026-11-05.2`가 표시된다. 남은 행이 있으면 같은 메뉴를 다시 실행한다.

작동 확인은 현재 실행 중인 규칙에 보고된 두 예문을 넣어 중간 누락과 문미 누락이 검출되는지 검사한다. 예전 검사 함수로 덮어써진 경우에는 실패로 안내하며, 전체 재검증도 기존 셀을 변경하기 전에 중단한다. 실제 시트의 셀 결과는 아래 확인 절차로 점검한다.

별도의 외부 AI 키나 API 연결은 필요 없다. `onEdit`는 사용자 편집 시 실행되는 기본 트리거이므로 별도 설치형 트리거를 만들 필요가 없다. 스크립트 편집기의 실행 버튼으로 `onEdit`를 직접 실행하면 편집 정보가 없어 작업을 수행하지 않는다.

## 이수자 명단 생성

`⚙️ 출석부 관리` → `📁 최종 이수자 명단 생성 (방식·기수 선택)`을 선택한다.

| 방식 | 사용 방법 |
| --- | --- |
| 선택 기수 명단 생성 | 실제 출석부에서 읽은 기수 목록 중 하나를 선택한다. 해당 기수의 명단만 만든다. |
| 전체 기수별 명단 생성 | 기수마다 각각 명단을 만든다. |
| 전체 통합 명단 생성 | 모든 기수의 이수 내역을 한 시트로 모은다. 같은 학생이 여러 강좌를 이수하면 여러 행에 표시된다. |

기존 전체 통합·전체 기수별 생성 메뉴와 함수명도 사용할 수 있다. 생성할 명단 시트가 이미 있으면 해당 시트를 그대로 유지하고 결과에 알린다. 기존 명단을 삭제·병합하거나 수기 세특을 지우지 않는다. 이수 판정은 아래처럼 1·2·3일 강좌의 모든 수업 출석을 기준으로 한다.

### 헤더 자동 필터

- 세 가지 생성 방식 모두 A1:I1 헤더부터 마지막 학생 행까지 전체 범위에 필터를 설정한다. 각 헤더의 드롭다운으로 해당 열을 필터링하거나 정렬할 수 있다.
- 이미 생성된 명단은 `세특 전체 재검증`을 실행하면 문장 검사와 함께 필터를 준비한다. 필터를 붙이기 위해 명단을 다시 생성할 필요는 없다.
- 기존 A1 필터가 A:I와 모든 기록을 포함하면 그대로 유지한다. A:H까지만 있거나 마지막 기록을 포함하지 못하면 범위를 확장하고 기존 열별 필터 조건을 보존한다. 이미 더 넓은 범위를 포함한 필터는 줄이지 않는다.
- 기존 필터가 A1에서 시작하지 않으면 그 필터와 조건을 유지하고 완료 안내에 `필터 확인`을 표시한다. 이때도 세특 검사는 진행한다. 해당 시트에서 필터 범위를 직접 확인한다.
- 필터 범위를 확장하다 실패하면 기존 범위와 열별 조건을 복원하고 처리 실패를 알린다.

### 1·2·3일 강좌의 출결 기준

특정 기수나 강좌명을 지정하는 예외 처리가 아니라 모든 출석부에 적용하는 공통 기준이다. 출석부의 7행이 날짜/차시 제목, 8행 이후가 학생별 출결이다.

| 수업 일수 | 출석부 준비 | 이수 조건 |
| --- | --- | --- |
| 1일 | D7에 1일차 날짜, E7은 비움 | D열 출석 |
| 2일 | D7·E7에 1·2일차 날짜 | D·E열 모두 출석 |
| 3일 | D7·E7·F7에 1·2·3일차 날짜. F7은 `3일차`라고 적어도 됨 | D·E·F열 모두 출석 |

- 출석은 체크박스의 실제 체크값 `true`만 인정한다. 미체크·빈칸·문자 `TRUE`·숫자 `1`은 출석으로 세지 않는다.
- F7은 실제 날짜 셀, `11/5`, `2026-11-05`, `11.5.`, `11월 5일` 등의 날짜 문자열 또는 `3일차`·`3차시` 표기를 인식한다. 날짜 뒤의 `(목)`·`(목요일)`도 허용한다. 기존 `비고`·`서명` 같은 제목은 3일차로 세지 않는다.
- 3일차를 표시했는데 E7이 비어 있으면 처리 오류로 안내한다. 2일차와 3일차의 날짜/제목을 먼저 확인한다.
- 달력상 연속된 날짜인지는 검사하지 않는다. 지정된 세 차시 모두 출석했는지 판단하므로 연기된 추가 수업에도 적용된다.
- 결석자 명단도 같은 일수와 체크값을 사용한다. 한 차시라도 미출석이면 결석 이력이며, `(대기)` 학생 중 어느 날에도 출석하지 않은 학생은 기존처럼 제외한다. 셋째 날만 출석한 대기자는 실제 참여 이력이 있으므로 나머지 날의 결석을 기록한다.

#### 기존 이틀 강좌에 하루를 수동으로 합치는 경우

1. 기준 출석부의 D·E열은 유지하고, F7에 셋째 날 날짜 또는 `3일차`를 적는다. F열에 기존 비고·서명 자료가 있다면 다른 열에 보존한 뒤 사용한다.
2. F8 이후에 체크박스를 준비하고, 추가 수업 출결을 **학번·이름을 대조하여** 해당 학생의 F열에 입력한다. 다른 출석부의 행 순서만 보고 붙여넣지 않는다.
3. 이후 이수자 명단을 생성하면 세 번 모두 출석한 학생만 기준 출석부의 기수로 집계한다. 출석부를 합치거나 다른 기수의 출결을 가져오는 작업은 코드가 자동 실행하지 않는다.
4. 합치기 전 추가 수업 출석부를 남길 경우에는 `보관_3기01강좌명`처럼 시트명 앞에 `보관_`를 붙여 별도 이수·결석 집계에서 제외한다. 단순히 숨기는 것만으로는 집계에서 제외되지 않는다.

자동 출석부 생성 양식은 기존대로 유지한다. 이번 기능은 사용자가 준비한 3일 출석부를 읽어 판정하며 시트 구조·체크박스를 자동으로 변경하지 않는다.

**이미 생성된 이수자 명단은 자동 갱신하지 않는다.** 새 조건을 반영해 다시 만들려면 기존 명단을 별도 이름으로 백업하여 세특을 보존한 뒤 생성해야 한다. 기존 세특은 학번·기수·강좌를 확인해 새 명단의 올바른 학생에게 옮긴다. `세특 전체 재검증`은 문장 검사 기능으로, 이수자 명단을 다시 산정하지 않는다.

## 세특 작성과 검사

- 적용 대상: `최종이수자명단`, `{기수}_최종이수자명단`의 2행 이후 G열.
- G열 입력을 확정하면 문제·검토 대상 표현을 빨간 글씨로 표시한다.
- I열 `오류 사유`에 `표현: 검출 사유`를 출력한다. 원본 검증기 사유와 아래의 추가 검토 사유를 함께 사용하며, 여러 사유는 줄바꿈한다.
- 일반 스페이스가 두 칸 이상 연속되면 한 칸으로 정리한 뒤 검사한다. 줄바꿈은 유지하며 자세한 범위는 아래 공백 정리 항목을 따른다.
- H열의 기존 바이트 계산 수식은 유지하고, 정리된 G열 본문을 참조해 바이트 수가 다시 계산된다. I열 사유와 빨간 표시도 같은 본문 기준으로 갱신한다.
- 문장을 수정하면 다시 검사하고 이전 검출 표시와 사유를 갱신한다. 연속 스페이스 정리 외에 맞춤법이나 문장 내용은 자동 교정하지 않는다.
- G열의 글자 색은 검증 기능이 검정/빨강으로 관리한다. 공백을 줄일 때도 남는 글자의 굵기·글꼴 등 다른 부분 서식과 링크를 보존한다.
- G열의 수식은 일반 문자열로 바꾸지 않고 건너뛰며 I열에 안내한다. 세특 본문은 직접 입력한 문자열을 사용한다.
- 정리 대상 외의 공백·숨은 문자는 기존 규칙에 따라 I열에 문자 이름·코드 등을 표시한다. G열 본문에 설명용 문자를 삽입하지 않는다.
- 빨간색은 교사가 검토할 대상을 뜻한다. `확인 필요`, `기재 의심`, `수정필요` 등의 원본 사유를 읽고 교사가 판단한다.

기존 명단도 G열을 편집하거나 아래 재검증 메뉴를 실행하면 I열을 준비한다. I열에 다른 제목·자료·수식이 있으면 그 자료를 보존하고 충돌을 안내한다. `오류 사유` 열에는 기능이 관리하는 메모가 붙으며 이 열은 검증 결과 전용으로 사용한다.

### 2026-11-05 연속 스페이스 자동 정리

- 일반 스페이스(`U+0020`)가 두 칸 이상 이어진 구간마다 첫 한 칸만 남긴다. 예: `탐구··결과를···발표함.` → `탐구·결과를·발표함.` (`·`는 이 설명에서만 쓰는 스페이스 표시).
- LF·CRLF·CR 줄바꿈은 그대로 유지한다. 탭·줄바꿈 없는 공백(NBSP)·전각 공백 등 다른 문자는 이 기능으로 바꾸지 않는다.
- 문장 앞뒤의 연속 스페이스도 한 칸을 남긴다. 앞뒤 공백 전체를 제거하는 동작은 하지 않는다.
- G열 입력 확정, 여러 행 붙여넣기, `세특 전체 재검증`에서 동일하게 동작한다. 처리 한도를 넘은 행은 재검증으로 이어서 정리한다.
- 정리된 본문에서 다시 검출하므로 이전 `연속 공백 사용` 사유는 사라지고, 남은 문제 표현의 빨간 표시와 I열 사유는 이동한 위치에 맞게 갱신된다. H열의 G열 참조 바이트 수식도 정리된 길이를 계산한다.
- G열 수식과 기존 I열 자료 충돌 시의 보호 동작은 그대로 유지한다.

공백이 그대로 남고 I열에 `연속 공백 5칸: 연속 공백 사용`이 계속 표시되면, 연결된 Apps Script에 이 저장소의 최신 전체 코드를 다시 교체·저장하고 시트를 새로 연 뒤 `세특 전체 재검증`을 실행한다. 예를 들어 `아버지가     법관이다.`는 `아버지가 법관이다.`로 정리되어 H열은 **30 → 26바이트**, I열은 **`법관이다: 어미 오류`만** 남아야 한다. 새 코드를 저장해도 이미 작성된 셀은 편집하거나 재검증해야 갱신된다.

### 2026-11-05 추가된 표기 검토 규칙

| 검출 조건 | I열 출력 예시 |
| --- | --- |
| 독립된 자음·모음(`ㄱ~ㅎ`, `ㅏ~ㅣ`)이 섞이거나 같은 종류로 2개 이상 붙어 있음 | `ㅁㄴ: 자모 연속 표기 오타 가능성(확인필요)` |
| 한 글자짜리 한글 어절이 3개 이상 연속됨 | `컨 텐 츠 제 작: 한 글자 어절 연속 사용(확인필요)` |

- 같은 유형의 여러 구간도 모두 검사하고 해당 구간을 빨간색으로 표시한다.
- `한 번 더`, `두 달 전`, `ㄱㄴ 순서`처럼 올바르게 쓴 표현도 확인 후보로 표시한다. 정상 표현을 자동으로 예외 처리하거나 원문을 고치지 않는다.
- 자모는 붙어 있는 입력만 검사한다. `ㄱ ㄴ`처럼 띄어 쓴 두 자모는 이 규칙의 대상이 아니다. 정상적으로 분해 저장된 한글 음절(NFD)은 독립 자모 오타로 처리하지 않는다.
- 한 글자 어절은 완성형 한글 한 글자만 있는 단위를 센다. 일반적인 세 어절 문장 전체를 검출하는 규칙이 아니다. 구절 양끝의 일반 괄호·따옴표·문장부호는 표시에서 제외하고, 문장부호나 줄바꿈을 넘어 다른 구절을 합치지 않는다.
- 이 두 규칙은 정해진 입력 형태의 검토 후보를 찾는다. 모든 오탈자·맞춤법·문맥 오류를 검사하는 기능은 아니다.

새 전체 코드로 교체한 뒤 이미 입력한 세특은 `세특 전체 재검증` 메뉴를 실행하면 추가 규칙까지 적용된다.

### 2026-11-05 어미·문장부호 확인 규칙

기존 어미 검사는 유지한다. 원본 검증기처럼 온점으로 나눈 각 구간의 마지막 한글 받침이 `ㅁ`·`ㄻ`인지 검사하는 방식이며, 어미·조사를 문법적으로 분석하는 기능은 아니다. 여기에 다음 두 검토 규칙을 추가했다.

| 입력 예시 | 빨간 표시 대상 | I열 추가 사유 |
| --- | --- | --- |
| `그렇게 됨을 판단함 추가적으로 분석함.` | `판단함` | `판단함: 문장부호 누락 의심(확인필요)` |
| `아버지가 의사임` | `의사임` | `의사임: 문장 끝 온점 누락(확인필요)` |
| `실험을 수행항` | `수행항` | 기존 `어미 오류`와 `문장 끝 온점 누락(확인필요)`를 함께 출력 |

- 문장 중간은 `함·됨·임·있음·없음·보임·깨달음·이끎·했음` 등 정해진 종결 후보로 끝난 어절 뒤에 공백/줄바꿈만 있고 다른 한글 어절이 이어질 때 찾는다. 여러 의심 구간도 모두 표시한다.
- `됨을`·`판단함에`·`함으로써`처럼 조사가 붙거나 연결형으로 이어진 어절은 후보에 해당하지 않는다. 뒤에 따로 쓴 조사, `함 자체가…`·`함 여부를…` 등의 연결 표현, `책임`·`포함` 등 지정된 일반 명사 예외도 제외한다.
- 기존 문장부호가 사이에 있거나 짝이 맞는 일반 따옴표 안의 표현은 문장 중간 누락 후보에서 제외한다.
- 본문 끝은 공백과 닫는 괄호·따옴표를 제외한 뒤 한글 어절로 끝나는 경우를 표시한다. `정리함.`·`정리함?`·`정리함!`처럼 문장부호로 끝나는 경우에는 이 사유를 추가하지 않는다.
- 온점이나 다른 기호를 자동 삽입하지 않는다. 교사가 수정하면 기존 방식으로 빨간 표시와 I열 사유를 갱신한다. H열 바이트 수식도 실제 G열 본문을 기준으로 계산된다.
- **중간 문장 검출은 문장 종결을 확정하는 기능이 아니다.** 명사형이 문장 중간에 쓰인 정상 표현도 표시될 수 있고, 후보 목록 밖의 형태나 `수행항 추가적으로…` 같은 중간 오타는 놓칠 수 있다. 본문 끝이 숫자·영문 등으로 끝나는 경우도 이번 한글 어절 끝 검사 범위에 포함하지 않는다.

기존 세특에 적용하려면 전체 코드를 교체·저장한 뒤 `세특 전체 재검증`을 실행한다. 남은 행이 있으면 같은 메뉴를 반복 실행한다. 이 과정에서 명단의 이수자는 다시 산정하지 않는다.

## 기존 세특과 대량 입력 재검증

`⚙️ 출석부 관리` → `🔎 세특 전체 재검증 (이어서 처리)`를 선택한다.

- 기존 이수자 명단의 G열 연속 스페이스를 정리하고 검사한다. 줄바꿈·나머지 본문·H열 수식은 보존한다.
- 한 번에 최대 200행을 처리한다. 남은 행이 있으면 완료 안내에 따라 같은 메뉴를 다시 선택한다.
- 처리 중인 다음 시트·행 위치만 문서 속성에 저장한다. 재검증이 끝나면 이 위치를 지운다.
- 편집 자동 검사도 대량 입력 시 처리 한도를 두며, 남은 행은 I열에 `재검증 필요`를 표시한다. 전체 재검증 메뉴로 이어서 확인한다.
- 재검증 도중 이미 지나간 행을 다시 수정하거나 시트 구조를 바꿨다면, 해당 행을 다시 편집하거나 진행 중인 검사가 끝난 후 전체 재검증을 한 번 더 시작한다.
- 기본 편집 트리거는 빠른 연속 편집 이벤트를 모두 보장하지 않는다. 대량·동시 입력 후에는 전체 재검증을 실행한다.

학생·강좌의 세특 본문 간 중복·유사도 검사는 보류 상태다. 기존 수강 신청의 일자·강좌 중복 명단 기능은 계속 사용한다.

## 실제 시트 확인 순서

실제 운영 적용 전 테스트 사본에서 다음을 확인한다.

1. 선택 기수 생성에서 1기와 11기가 구분되는지 확인한다.
2. 기존 명단에 작성한 G열 세특·H열 수식이 재생성 시 보존되는지 확인한다.
3. G열에 `유튜브 영상을 분석함.`, `특허의 원리를 조사함.`, `실험 결과를 발표함~`을 각각 입력해 빨간 표시와 I열 사유를 확인한다.
4. `AI 모델을 활용함.`으로 수정하고 표시와 사유가 해제되는지 확인한다.
5. `컨 텐 츠 제작 중 ㅁㄴ 오류를 점검함.`을 입력해 두 추가 사유와 표시 위치를 확인한다. `한 번 더 검토함.`도 확인 후보로 표시되는지 확인한다.
6. G열에 두 칸·세 칸 스페이스와 줄바꿈이 섞인 문장을 입력해 스페이스는 한 칸이 되고 줄바꿈은 유지되는지, H열 바이트 수와 I열 사유·빨간 표시가 정리된 본문과 일치하는지 확인한다. 굵기 등 부분 서식과 링크도 확인한다.
7. 여러 G열 셀 붙여넣기·삭제·전체 재검증을 확인한다.
8. 3일 강좌의 F7과 F열을 준비하고 전일 출석·각 차시 결석·빈칸을 넣어 이수자와 결석자 결과를 확인한다. 기존 F7이 `비고`·`서명`인 1·2일 강좌의 결과도 확인한다.
9. `그렇게 됨을 판단함 추가적으로 분석함.`과 `아버지가 의사임`을 입력해 추가 사유와 표시 위치를 확인한다. 문장부호를 보완하면 사유가 해제되는지도 확인한다.
10. 새 명단의 A:I 헤더 필터와 전체 데이터 범위를 확인한다. 기존 명단은 재검증 후 필터가 붙는지, 기존 열별 조건이 유지되는지 확인한다.
11. 기존 출석부 생성, 신청 중복·대기·담임 명단, 결석자 관리, PDF 출력이 정상인지 확인한다.

현재 개발 환경에서는 실제 Google 스프레드시트에 적용하지 않았다. 실제 권한·화면 표시·처리 시간은 이 테스트 사본에서 확인해야 한다.
